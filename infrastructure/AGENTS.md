# Infrastructure Conventions

- **Environment directories**: `infrastructure/development/` (HTTP only) and `infrastructure/release/` (HTTPS, Let's Encrypt, web→websecure redirect). Each holds its own `docker-compose.yml`, `Taskfile.yml`, and `traefik/`. Copy `infrastructure/.env.example` into each environment directory as `.env`. Switch with `task up env=release` (default is development).
- **In a git worktree, `task up` (development only) copies `.env` from the main checkout** when the worktree has none (`ensure-env` in `development/Taskfile.yml`). It never overwrites an existing file, and `release/` has no such fallback — it simply fails without `.env`.
- **`infrastructure/docker-compose.example.yml`** is the baseline compose template (same service structure as the per-environment files): apply structural service changes there first, then mirror them into `development/` and `release/`.
- **Traefik routing**: traefik uses only the file provider — routes live in each environment's `traefik/dynamic.yml` (e2e: `e2e/traefik/dynamic.yml`), never in container labels, and no compose file mounts `/var/run/docker.sock` (do not reintroduce the docker provider: the socket is host root). To expose a service, add a router, a service addressed by compose service name (`http://backend:8080`), and any middleware there. Paths are dispatched by `PathPrefix` (backend = `/api`, static = `/static`, frontend = everything else). If an app is unaware of its prefix, add a `stripPrefix` middleware (e.g. `backend-strip`). The file provider gets no compose interpolation; `release/traefik/dynamic.yml` reads the TLS domain through traefik's `{{ env "APP_DOMAIN" }}` template, so the gateway must receive `APP_DOMAIN` in its `environment`. A malformed `dynamic.yml` leaves traefik with zero routers while its `--ping` healthcheck stays healthy.
- **DB / Redis**: referenced by the service names `database` / `cache`. Migrations are Liquibase (`backend/src/main/resources/db/changelog/`).
- **Network and host aliases**: in `development/` (and the example template) the `gateway` service carries the aliases `store1.kizuna.test` / `kizuna.test`; `release/` has none, since it is reached through real DNS. The frontend proxy (`frontend/src/proxy.ts` → `shared/lib/proxy/storeResolver.ts`) tells store sites from the app host by Host, and callers inside the compose network resolve those names through these aliases. Development must also set `APP_DOMAIN=kizuna.test` in its `.env` — the example file ships `kizuna.jp`, and `storeResolver` treats only `APP_DOMAIN` as the app host, so with the example value the aliased `kizuna.test` root resolves as a _store_ instead of the app host (admin console). Renaming an alias is the silent failure — it degrades into a DNS failure inside whatever is calling.
- **E2E does not use this stack.** `e2e/docker-compose.e2e.yml` stands up its own disposable copy (same services, tmpfs data, no host ports, project name derived from the worktree) so that e2e and the development stack — and e2e runs from worktrees with distinct basenames — do not collide. Each gateway resolves `backend` / `frontend` / `storage` through its own compose network's DNS, so the stacks cannot claim each other's routes.
- **Secrets**: `.env` must not be committed.

## Services (compose project `kizuna`)

Six services: `database`, `cache`, `backend`, `storage` (SeaweedFS, serves `/static`), `frontend`, `gateway`. Images and ports live in the compose files — read them there rather than trusting a copy here. Two things the compose files do not make obvious:

- **Service name ≠ container name** for `cache` (container `redis`) and `gateway` (container `traefik`): from the repository root, `task -d infrastructure/development logs service=cache` takes the service name, raw `docker` commands take the container name.
- **Storage access**: S3 is exposed through `/static` on the gateway. Development and the example template enable the Admin UI at `http://localhost:23646`, bound to host loopback only. Release and E2E keep the Admin UI disabled with no storage host ports. WebDAV is disabled in all environments.
