# ドメイン文書

エンジニアリングスキルがコードベースを調査するときの参照規約。

## 配置と読む順序

このリポジトリは single-context 構成を使う。

- ドメイン用語や振る舞いを調べる前に、ルートの `CONTEXT.md` を読む。
- 設計判断を扱う前に、`docs/README.md` の ADR 索引から対象領域に関係する `docs/adr/` の文書を読む。採用状態も確認する。
- 参照文書が存在しない場合は、そのまま調査を進める。文書の作成自体を前提作業にせず、用語や設計判断が確定したときに `domain-modeling` で記録する。

## 用語の使用

課題、提案、仮説、テスト名でドメイン概念を表すときは、`CONTEXT.md` の語彙を使い、そこで避けるとされている同義語へ置き換えない。

必要な概念が用語集にない場合は、既存の用語で表せるか確認する。実際の不足であれば、`domain-modeling` で扱う論点として記録する。

## ADR との矛盾

提案が有効な ADR と矛盾する場合は、対象の ADR と再検討が必要な理由を明示する。

`docs/legacy-business/` は旧システムの調査資料であり、現在の Kizuna の振る舞いの正本として扱わない。
