# 業務書込の監査接続と安全な記録項目

## 基点と接続単位

現在の合流基点は `9351275ea034fedd96d35f5968f2d335196cc6cd`（認証失効修正#999、通常受注監査#996を含む）。実行・監査基盤の仕様は [0395-task-execution-audit.md](0395-task-execution-audit.md) に従う。手動実行の個別権限と SERVICE の現在授権、招聘機能、通知基盤、入力ログの機微情報除外を含む合流済みの実装は維持する。#395 全体の完了とは分けて、各業務の書込サービス単位で実装・検証する。

認証主体・対象店舗・操作名・対象 ID・結果・日時は公共 sink に渡し、緊急昇格では検証済みセッションの昇格 ID を関連付ける。業務と成功監査を同じ取引に保存する。拒否・競合・rollback を成功履歴にしない。読み取り、変更しない preview、同じ確定済み結果を返す replay は新たな成功変更を作らない。

## 対象別の棚卸し

| 業務境界 | 基点での状態 | 記録対象と制限 |
| --- | --- | --- |
| SERVICE、ロール、スタッフ授権、店長、アカウント状態 | 接続済み | 主体・ロール・店舗 ID、本人種別、範囲・状態。パスワードは含めない |
| 緊急昇格の発動・撤回、通知要求 | 接続済み | 昇格 ID、理由、状態。通知配信は #394 の担当 |
| 受注訂正・完了無効化 | 接続済み | 訂正 ID、金額・報酬・版・状態・理由。既存の訂正正本を参照 |
| 顧客統合、手動ポイント調整 | 接続済み | 統合・調整 ID、対象 ID、残高・状態。独自の第二監査表は作らない |
| 通常受注7操作 | #996 合流済み | 下表の許可項目を前後で比較し、受付や提供・会計の変更を辿る |
| 帰属訂正・無効化、伝票再発行、ポイント巻戻し | 後続 | 帰属・訂正・台帳 ID、状態・金額。トークン生値・digestは含めない。#820 の実行器/失効処理と重複変更しない |
| 顧客と会員の関連付け・解除 | 後続 | 関連区間 ID、顧客・会員 ID、状態、既存理由の参照 |
| キャスト作成/編集/削除・公開・在籍、招待、カスタム項目 | 後続 | 在籍/状態履歴/設定 ID、状態、公開区分、版。招待秘密・個人情報・任意入力値は複写しない |
| シフト作成/編集/削除・公開、申請決定、出勤実績 | 後続 | 班次・申請・実績・在籍 ID、日時、状態、版。自由記述は必要性を個別に確認 |
| 顧客作成/編集/削除 | 後続 | 顧客 ID、状態・変更項目名。会員関連付け/解除とは別に扱う |
| 連絡先、用途許諾、優先関係 | #1000で実装・検証中 | 連絡先/既存履歴 ID、種類・許諾状態・優先関係・変更項目名。[5入口の契約](0395-contact-audit.md)。値・許諾根拠原文は複写しない |
| 店舗プロフィール・サービス設定・ファイル登録 | 後続 | 設定/版本 ID、価格・時間・報酬、公開状態、必要なファイルメタデータ。外部ストレージの確定順序は別途検証 |
| 招聘・通知・定期ポイント等の新機能 | 各機能の担当 | 公共 sink に接続。#396 / #394 / #820 の所有ファイルをこのバッチで変更しない |

平台の設定変更や本人専用の登録・申請などは、緊急昇格で到達する店舗書込とは別に棚卸しする。上表をシステム全書込の完了宣言には使わない。保持年限・実運用スケジュール有効化・未実装の月次ロック解除も未完了のまま残る。

## 合流済みの通常受注7入口

| `OrderService` の入口 | 操作名 | 対象・由来 |
| --- | --- | --- |
| `create` | `ORDER_CREATED` | 新しい受注。before は空 |
| `update` | `ORDER_UPDATED` | 更新前後の受注 |
| `complete` | `ORDER_COMPLETED` | 提供・会計を完了した受注。伝票トークンを含めない |
| `cancel` | `ORDER_CANCELLED` | 取消前後の受注。理由正本は受注に保持 |
| `confirmApplication` | `ORDER_APPLICATION_CONFIRMED` と `ORDER_CREATED` | 申請の前後と新しい受注。受注側の由来は申請 ID |
| `declineApplication` | `ORDER_APPLICATION_DECLINED` | 謝絶前後の申請。理由正本は申請に保持 |
| `start` | `ORDER_STARTED` | 提供開始前後の受注。開始理由正本は受注に保持 |

受注の許可項目は、版・状態、顧客/在籍/受付担当/申請会員の ID、営業日、予定/実績時刻、人数、受付経路、コース版本 ID、費用総額・固定報酬・発生済み報酬・自動付与ポイント・総時間、開始/完了/取消日時、完了無効化状態、再提供元 ID、費用行の ID・種別・金額・時間・報酬・採用設定版本 ID とする。子明細は選んだ項目だけを安定順で記録し、明細名など任意入力を含めない。

連絡先・住所・備考・担当者宛メッセージ・自由形式の媒体等は値を比較するためだけに使い、監査へは変更項目名だけを渡す。要求全体・entity 全体・例外・原メール・パスワード・トークンをシリアライズしない。昇格理由は昇格 ID、取消/開始/謝絶理由は元の業務 ID から正本を参照する。

申請は版・状態、営業日・希望時刻・人数、希望在籍/申請会員/生成受注/処理者の ID、処理日時、連絡先取込件数に限定する。希望原文・申請者氏名・連絡先・同意時の連絡先写しを含めない。

## 検証

各成功入口の前後値と操作数、preview・不正状態・版競合で記録が増えないこと、監査失敗時の業務 rollback、普通スタッフと緊急昇格の主体/昇格 ID、異店舗・権限拒否を検証する。秘密のダミー値を受注入力に含め、監査 API の内容に混入しないことを確認する。最終検証は Taskfile と独立した Standards / Spec review を使う。
