# 02: 手動受付した口コミを承認し、公開許可の撤回と訂正を追う

親課題: #394。実装票: [#998](https://github.com/kanghouchao/Kizuna/issues/998)。仕様: 394-A 口コミの手動受付・承認・取り下げ承認済み契約。

状態: **実装済み・PR審査待ち**。状態系列・跨端契約・モジュール契約・試験面・単独縦切片の粒度は主タスク承認済み。

## 何を作るか

店舗担当者が紙面・口頭・既存電子記録から口コミを手動受付し、内容を固定したまま理由付きで承認・却下・取り下げを行う。別の公開許可記録と撤回、旧内容を書き換えない訂正再受付、履歴を同じ画面から辿る。公開側に渡す限定した投影は現在の承認・有効許可・未取り下げを毎回検証し、実公開や外部連絡を開始しない。

## 受け入れ基準

- [x] 全受付がスタッフによる記録と分かり、顧客本人の認証済み投稿や購入者確認と表示しない。
- [x] 新規受付・照会・内部承認／却下・取り下げが、既定授与のない独立権限と現在の店舗授権を通過する。
- [x] 受注関連は任意で、指定時の同店・可視・完了資格を個人情報を返さないorderの契約で検証する。
- [x] 承認と公開許可を別に保持し、無許可でも内部承認できる。許可の取得日時・根拠・記録者を追跡できる。
- [x] 許可だけを撤回でき、内部承認を残したまま限定した投影から除外される。WITHDRAWNは復帰せず、REVOKEDへの再許可は拒否する。
- [x] 本文等の訂正は同一取引で旧受付を取り下げて新規PENDING／NOT_GRANTEDを作り、一対一の履歴で結ぶ。
- [x] 同キー同内容の再生は後続状態が変わっても原操作と現在詳細を返す。異内容・旧version・別キーの反復は409で、履歴と監査を増やさない。
- [x] 並行要求、旧状態での承認、許可撤回、二重訂正、監査失敗の境界を実DBで検証する。
- [x] 一覧の検索・sort・Page、履歴のCursorPageを契約どおり制限し、一覧型に本文・根拠・受注情報を含めず、適格な公開投影にも根拠・理由・受注情報を含めない。
- [x] 公開向け内部投影は現在の三条件を強制し、本文と表示名以外の機密情報を返さない。匿名HTTP・公開サイトは追加しない。
- [x] 404/409/権限変化/旧応答/結果不明から回復でき、画面内で同じ要求を再照会できる。機密入力をブラウザ永続storageへ保存しない。
- [x] 実外部送信・公開・報酬付与を伴わず、Taskfile門禁、code-review、調整済み専用E2Eで一連の操作が成功する。

## 視覚・探索基準

390pxと通常幅、明暗テーマ、Tab/Enter操作で、手動受付・承認・公開許可・公開未連携の区別が読み取れる。許可撤回と口コミ取り下げの違い、訂正時に承認・許可を引き継がないことを確認前に説明する。
