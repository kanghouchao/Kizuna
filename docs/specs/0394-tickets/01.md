# 01: 許可された受注・申請の業務メールを作成し送信履歴を追う

親課題: #394。依存: #395 実行・監査基盤と #820 の手動実行権限・現在授権再検証。最終 PR は両依存が取り込まれた master に合わせる。

担当者が作成・確認・予約・明示再試行する画面から、現在の連絡可否を強制通過したメール送信と試行履歴までを実装する。

- [x] 店舗・権限・主体を検証して作成、閲覧、queue、retry を分離する。
- [x] 同一要求の再生、異なる冪等キー内容の拒否、反復遷移の拒否を実 DB で検証する。
- [x] ORDER / ゲスト APPLICATION の両方で最新の許可された宛先だけを使用する。
- [x] TaskExecutor と永続イベントを接続し、外部 I/O は DB 取引の外で実施する。
- [x] 未設定、未送信失敗、結果不明、提供方受理を区別し、不明結果を再送しない。
- [x] UI の権限隔離、古い応答、二重操作、回復操作を検証する。
- [x] 注入fakeによる送信検証、SMTP未設定の実スタック E2E と Taskfile 全門禁が通る。
