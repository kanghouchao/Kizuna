# 顧客一覧の最終来店日・会員残高と目印

状態: HTTP 契約承認済み（2026-09-26）。対象: #964（増補仕様 #955）。

## 一覧の HTTP 契約

`GET /store/customers` は既存の `Page<CustomerSummaryResponse>` を 200 で返す。検索 `search`、区分 `classification` と既存の一覧項目を維持し、各行に次の項目を追加する。

| JSON 項目 | 型・省略可否 | 意味 |
| --- | --- | --- |
| `last_visit_date` | `YYYY-MM-DD` 文字列。対象受注がなければ省略 | 当該店舗・顧客に属する、完了済みかつ無効化されていない受注の最大 `business_date` |
| `point_balance` | 64 ビット整数の JSON number。ACTIVE 関連がなければ省略 | 現在の関連会員のプラットフォーム全体残高。既存の会員残高照会と同じ定義を使い、残高零は `0` を返す |

既存の `member_linked` は必ず boolean を返す。未関連を零残高へ変換しない。顧客の残高列は作らない。

番号付きページングは既存の `page`（0 始まり、既定 0）、`size`（既定 20、既存の共通上限）と総件数を使う。`sort` に `lastVisitDate,asc` / `lastVisitDate,desc` / `pointBalance,asc` / `pointBalance,desc` を追加する。ソート値は Spring Data の既存形式に合わせ、応答の JSON キーとは区別する。

新しい二つのソートは欠損を常に末尾へ置き、未指定の一意な副キーには `id,asc` を補う。明示的な `id` の方向指定は既存の共通規約に従う。ソートは全対象行へ適用してからページを切り出す。既存の登録日時順を維持し、UI の初期表示は `createdAt,id,desc` とする。新しいソートを選ぶと UI は先頭ページへ戻る。同一データに対する両方向のページ移動で重複・欠落がないことを保証する。ページ間の同時更新を固定するスナップショット契約は追加しない。

## 目印の HTTP 契約

既存の `landmark` 列を使用する。項目は最大 255 文字の文字列とし、顧客一覧へ住所の詳細を追加しない。

| メソッド・端点 | 要求・応答の追加 | 成功 |
| --- | --- | --- |
| `GET /store/customers/{id}` | 詳細応答に `landmark`。保存値が null なら省略 | 200 |
| `POST /store/customers` | 要求に任意の `landmark`。省略・null は未設定。応答の顧客詳細にも反映 | 201 |
| `PUT /store/customers/{id}` | 要求に任意の `landmark`。省略・null は変更なし、空文字 `""` は明示的に空欄へ更新。応答の顧客詳細にも反映 | 200 |

空文字は空文字として保存・再取得できる。既存の住所等と同じ部分更新規約を使い、独自の空白正規化は加えない。画面では「目印」と表示し、作成・編集の共通フォームにも配置する。

## 授権・失敗応答

対象端点はすべて既存の `PERM_CUSTOMER_MANAGE` を要求する。店舗コンテキストは `X-Role: store` と `X-Store-ID`、データ分離は既存の `@StoreScoped` を使う。顧客一覧は現在店舗の未統合顧客だけを返し、詳細の旧 ID 解決は既存の統合規約に従う。

- 401: 未認証または無効な認証。
- 403: 権限不足または店舗コンテキスト・店舗授権の拒否。
- 400: 不正な入力（`landmark` の長さ超過等）。
- 404: 詳細取得・更新対象が不存在または店舗作用域から不可視。
- 409: 既存の更新競合条件に該当する場合。新しい業務競合条件は追加しない。

失敗応答は既存の `{ "error": "…", "details": { "field_name": "…" } }`（`details` は任意）。会員・公開 DTO の項目は変更しない。
