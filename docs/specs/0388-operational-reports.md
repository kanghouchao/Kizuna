# 0388 運営金額集計と帳票出力

## 問題

店舗・原営業期間ごとの完了受注の請求額と固定報酬を、権限内で照会して CSV / XLSX に持ち出せる必要がある。旧 #388 の精算台帳・実収未収・精算範囲の前提は、現行の受注・授権の境界と一致しない。

## 解決

完了受注の現在の有効事実を原 `business_date` で集計する。原期間への訂正・無効化は再照会・再出力へ反映する。生成時点・対象期間・集計条件を明記し、過去時点の復元や独立した保存台帳は持たない。

## 利用者の要求

1. 店舗担当者は単店の営業日期間を指定して有効完了件数・請求額・発生済み固定報酬を確認する。
2. 集合担当者は授権された店舗集合またはその一店だけを照会する。
3. 担当者は日別・月別・店舗別に集計する。
4. 担当者は一覧のページと無関係に対象全件を出力する。
5. 担当者は無効化件数と有効零の根拠を区別する。
6. 担当者は原営業日・受注 ID・受注版を出力して現在の受注と突き合わせる。
7. 閲覧担当者でも出力権限が無ければダウンロードできない。
8. 授権外店舗、解決できない集合、権限のない主体からの照会は拒否する。
9. 日本語と先頭零を保った Excel 出力を利用できる。
10. 出力が大きすぎる場合は部分帳票を受け取らず、条件を狭めて再試行する。
11. 画面の古い検索応答が新しい条件へ混入しない。

## 決定

- 状態 COMPLETED のみ対象。未完了・取消は含めない。有効完了件数は無効化を除外し、無効化件数を別記する。
- 請求額は `total_fee`、報酬は `accrued_remuneration`。無効化は双方零。料金明細の無符号表示額、元の usedPoints、現在値と訂正スナップショットの累積から再算出しない。
- サービスの現在設定で過去を再計算しない。訂正は原期へ反映し、訂正時期へ移さない。
- 1 回の読み取りは REPEATABLE_READ。取得した必要項目だけの全件射影から総計・グループ・出力明細を作り、顧客・キャスト氏名や連絡先を取得しない。
- 共通の上限を超えた照会・出力は 503 で全体失敗。既定は 20,000 受注、366 日、400 万文字、16 MiB、25 秒、DB 読み取り10秒。生成枠は各プロセス1件。
- `order::reporting` が受注事実を公開し、帳票モジュールが集計と形式を所有する。DB変更は不要。注文上限は設定でも100,000を超えられず、単件金額は非負int。最大合計214,748,364,700,000はJavaScriptの安全整数とExcelの15桁内に収まり、異常値は503で拒否する。
- 閲覧 OPERATIONAL_REPORT_VIEW、出力はさらに OPERATIONAL_REPORT_EXPORT。いずれも SHARED、既定ロールへの授与なし。単店側は ORDER_MANAGE、集合側は ORDER_SET_MANAGE も要求する。
- CSV は UTF-8 BOM、CRLF、全セル引用と引用符二重化。文字列セルに単引用符を付ける（IDの先頭零を保護し、数式開始文字を無害化するための出力規約）。CSV再保存後の解釈は表計算ソフトに依存するため、忠実な型保持には XLSX を用いる。
- XLSX は文字列／数値／真偽値を明示する。数式・マクロ・外部リンクを作らない。Apache POI の固定100行窓と圧縮一時ファイルを使用し、終了時・失敗時とも一時ファイルを破棄する。

## HTTP 契約

GET `/store/operational-reports` と `/platform/operational-reports`。
必須 `from` / `to` は ISO 営業日（両端を含む、1..9999年、最大366日）。`group_by` は day（既定）/ month / store。集合側の任意 `store_id` は正の整数、省略時は授権店舗集合。単店側は既存店舗ヘッダーを使う。
`page` は0始まり、`size` は既定20・上限100。グループは店舗ID、期間の順で全順序。

200 は from/to/group_by/generated_at/basis、total_order_count（有効完了件数）、invalidated_order_count、total_fee、total_remuneration 、stores（store_id/store_name、注文のない授権店も含む）と rows（Spring Page）。行は store_id/store_name/period（dayは日、monthは月、storeは空文字）/order_count/invalidated_order_count/total_fee/total_remuneration。件数・金額は64bit整数。

GET 同経路 `/exports` は同じ条件と必須 `format=csv|xlsx` を取る。ページに関係なく全グループと全根拠受注を返す。CSV は record_type=metadata/summary/order の共通列、XLSX は条件・集計・受注明細の3シート。明細は受注ID、版、原営業日、無効化、有効請求額・固定報酬。認証付き attachment、Cache-Control: no-store。

401 未認証、403 機能／店舗／集合不足、400 条件不正、404 指定店舗不存在、503 容量・時間・同時生成上限。既存 error/details JSON に従い、失敗時に attachment ヘッダーや部分ファイルを返さない。

## テスト

HTTP境界を中心に権限と最小限のDTO、実データE2Eで店舗フィルタと訂正・無効化・跨月・積算を検証する。生成器では日本語、引用、数式開始文字、先頭零、2000件超、合計整合、資源超過後の再試行を検証する。既存月次給与明細の REPEATABLE_READ と認証ダウンロードが先行例。

## 対象外

実収・未収・支払状態、精算台帳・締め、精算範囲、税区分、広告費、利益・ROI、会計ソフト固有科目、過去時点復元、定期配信。日額保証・ボーナスは下記の後続接続で扱い、現行v1の出力にはまだ含めない。未実装・未確定の金額を零として表示しない。

## 設計検討（grilling）

事実の根拠 → 現行受注、帰属 → 原営業日、訂正 → 再照会で原期へ、範囲 → 役割×授権店舗、金額 → 完了請求額と固定報酬、出力 → 独立権限・全件・全体失敗、外部接続 → 未定義額を導入しない、という決定木を現行実装と委任指示で確定した。APIは主タスクによる前後端契約の承認済み。公開 issue の更新は明示指示まで行わない。

## 実装・検証記録

実装した切片は単店照会、単店全件出力、授権店舗集合の照会・出力。個別の受け入れ項目は [01](0388-tickets/01.md)、[02](0388-tickets/02.md)、[03](0388-tickets/03.md) に対応する。

- Docker Taskfile の `lint`、`test`、`build` は exit 0。単体テストは backend 1,655件、frontend 168 suite / 1,576件。
- 専用 E2E の帳票シナリオは exit 0。2,001件の全件 CSV/XLSX、JWT改竄・授権外店舗・出力権限不足の拒否、無注文店、DBロック下の同一時点読み取り、原期訂正・無効化を検証。
- 全量 `task e2e` は exit 0、73シナリオすべて成功（12.1分）。明暗テーマの1024px画面とキーボード移動、CSV/XLSXを成果物として記録。
- 規約と仕様の独立したコードレビューを行い、修正後の再確認で阻害指摘なし。

日額保証・ボーナスは #387 / PR #1021 で規則と金額正本が実装済み。#388 の後続接続は [承認済みAPI契約](0388-remuneration-report-contract.md) に従う明示選択式の接続を実装・検証した。既定のv1には追加額を含めず、追加参照権限を持つ要求だけがv2を取得できる。広告費・費用は #389 の仕様確定待ちを維持する。これらを零の金額項目として先行追加しない。旧精算台帳・実収未収・精算範囲は廃棄済み前提であり、残存実装課題として扱わない。

一時ファイルは POI 5.5.1 の `close()` が破棄する。正常出力・生成中の文字数超過・出力容量超過・書き込み IOException の後に、実際に作成したファイルの消滅と専用ディレクトリが空であることを回帰テストで確認する。根拠は [5.5.1 の close 実装](https://github.com/apache/poi/blob/REL_5_5_1/poi-ooxml/src/main/java/org/apache/poi/xssf/streaming/SXSSFWorkbook.java#L858-L884)。
