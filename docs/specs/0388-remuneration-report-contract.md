# 0388 日額保証・ボーナスの帳票接続

## 状態と調査結果

2026-10-09 に利用者が API 契約を承認。以下の契約に従い実装する。

基点は master `28a82c0b0f69e43755a42d4f4f19959808537dd1`。
#388 の現行本文と PR #991 / #1021 を照合した。既存の運営帳票には単店・授権店舗集合の照会、日別・月別・店舗別集計、全件 CSV / XLSX、資源制限、同一時点読み取りがある。
日額保証とボーナスの正本・計算・履歴は remuneration モジュールに実装済みだが、運営帳票は order::reporting の受注事実だけを読んでいる。
本人明細は既存の本人専用境界を維持し、本接続で新たな本人向け帳票 API は作らない。既存月次 PDF は受注報酬のみという範囲を維持する。

## HTTP 契約

既存の次の四経路を拡張し、新しい経路は作らない。

- GET `/store/operational-reports`
- GET `/platform/operational-reports`
- GET `/store/operational-reports/exports`
- GET `/platform/operational-reports/exports`

共通の任意 query `include_remuneration: boolean`（既定 false）を追加する。既存の from / to / group_by / store_id / page / size / format の型・省略可否・上限は [既存契約](0388-operational-reports.md#http-契約)を維持する。閲覧は Spring Page（page=0、size=20、最大100）、出力はページに依存せず全件。

既定 false は JSON・CSV・XLSX の既存契約と `completed-orders-current-v1` を維持する。true は `completed-orders-remuneration-current-v2` とし、受注・保証・ボーナスを同一 REPEATABLE_READ 取引で読む。生成時刻を共通化する。

成功 200。未認証401、機能／店舗／集合不足403、条件不正400、指定店舗不存在404、容量・時間・同時生成・金額の安全上限超過503。既存 error/details、認証付き attachment、no-store を維持し、失敗時に部分ファイルは返さない。

### 授権

既存の店舗側 ORDER_MANAGE / 平台側 ORDER_SET_MANAGE と OPERATIONAL_REPORT_VIEW を維持し、出力は OPERATIONAL_REPORT_EXPORT も要求する。include_remuneration=true は追加で REMUNERATION_VIEW を要求する。false の利用者へ新しい給与額を返さない。実ロールや既定ロールへの授与は行わない。

画面は REMUNERATION_VIEW 保持者に「日額保証・ボーナスを含める」を提示する。検索と出力は適用済み条件を共有し、切店・切日期間・オプション変更後に古い照会／出力応答を採用しない。

### JSON

既存 total_remuneration は受注固定報酬のまま保つ。true の場合だけ、総計と各 rows.content 要素に `remuneration` オブジェクトを追加する。false ではこのフィールドを省略する。

| フィールド | 型・null | 意味 |
| --- | --- | --- |
| known_guarantee_total | 非負整数、必須 | 計算可能な日額保証補差だけの小計 |
| guarantee_total | 非負整数またはnull、必須 | 全対象日の保証が計算可能なら合計。未確定日が一つでもあればnull |
| bonus_total | 非負整数、必須 | 帰属日が期間内の有効付与額。取消は0 |
| total | 非負整数またはnull、必須 | 受注報酬＋保証補差＋ボーナス。保証未確定ならnull |
| pending_attendance_days | 非負整数、必須 | PENDING_ATTENDANCE の本人・店舗・営業日数 |
| not_configured_days | 非負整数、必須 | NOT_CONFIGURED の本人・店舗・営業日数 |

null は画面で「未確定」と表示し、既知保証小計と状態別日数を併記する。日数は店舗内の暦日数ではなく本人ごとの判定数である。保証やボーナスのみ存在する期間も集計行に含める。並びは店舗ID・期間。任意の from / to に日単位で裁切り、期間外の未確定日を総計・状態別日数へ混入させない。

## 金額と根拠

既存の AttendanceDuration / DailyGuarantee / RemunerationAmounts の意味を再利用する。本人・店舗・保存済み営業日ごとに、歴史在籍を跨ぐ有効な閉合出勤を合併し、4時間以上で日別不足分を計算して期間へ足す。翌日の高報酬やボーナスで不足分を相殺しない。既存の受注固定報酬には日別補差と有効ボーナスだけを加え、受注額を含む月次明細の total を再加算しない。開放区間、未設定、停止の判定は remuneration と同一で、欠損を0へ置換しない。

受注額は保存済み完了受注の現在有効額。訂正・無効化は元営業日の期間へ反映する。ボーナスは保存済み award_date に帰属し、訂正後の帰属日・額と取消状態を再照会で反映する。保証条件は有効開始日から次の条件まで適用する。

JSON の安全整数上限を超える合計は拒否する。XLSX は既存の数値セル型を保持し、Excel の15桁で正確に表現できない金額（999,999,999,999,999円超）は丸めず出力全体を503にする。CSVは整数の十進表現を使う。

## 出力互換性

false の16列・3シート・行種別とファイル名を保つ。true は既存16列を同順のまま保持し、保証既知小計、保証額、ボーナス額、報酬合計、状態別未確定日数および根拠列を末尾に追加する。未知金額は空欄と状態列で表し、0と区別する。JSON・画面・CSV・XLSXで null、既知0、既知小計の意味を一致させる。既存生成器の List.of と toString へ null を渡さず、出力境界で未知値を明示的に変換する。

CSV に remuneration_day と bonus の根拠行を追加し、XLSX に「日別報酬根拠」「ボーナス根拠」の2シートを追加する。

日別根拠は店舗ID・本人ID・営業日・受注報酬・保証条件ID／開始日／状態／日額・閉合出勤時間・開放区間有無・保証判定状態・保証補差・ボーナス日計を持つ。ボーナス根拠は店舗ID・本人ID・付与ID・版・帰属日・取消有無・現在有効額を持つ。顧客情報・本名・源氏名・内部理由・操作者は取得／出力しない。総計に根拠行の金額を再加算しない。

本人・日付の組数、条件、ボーナスを含む入力事実と生成行の双方に上限を設け、受注以外の大量出勤・条件・付与でも無制限に取得しない。追加入力（出勤区間＋保証条件＋付与）の総件数と生成人日数は、それぞれ既存の maxOrders（既定20,000、設定可能上限100,000）以下とする。条件は対象店舗の終了日以前の有効版本を取得し、件数上限には当期の出勤がない本人の版本も含める。既存の時間・文字数・容量・同時生成予算を全根拠へ適用する。超過は全体失敗とし、上限取得で末尾を切り捨てた帳票を成功扱いにしない。

## 検証計画

- 単店／集合／本人境界：追加参照権限の欠如、直接API、授権外店舗、履歴在籍、本人APIの情報項目維持。
- 集計：4時間境界、重複区間、深夜帰属、日別補差の月合計、賞与独立、未終了／未設定／停止、受注無し保証／賞与。
- 訂正：翌月から原月の受注訂正・無効化、保証変更、ボーナス訂正・取消、期間移動。
- 一貫性：同時更新下の受注・出勤・条件・付与を一つのスナップショットで検証。
- 出力：既定v1の互換性、v2のCSV／XLSX全件、未知値、数値精度境界、数式保護、上限超過、例外後の資源解放。
- UI／E2E：切店、期間切替、ページ切替、再照会連打、出力連打、遅延した旧応答、明暗・狭幅・キーボード。
- 最終検証は Taskfile の lint / test / build / e2e とし、条件付き実DB試験の実行とスキップを分けて記録する。
