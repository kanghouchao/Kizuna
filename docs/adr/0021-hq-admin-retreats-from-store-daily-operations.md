# HQ 管理者はアカウント生命周期・ロール定義・統治層の授与を担い、店舗の日常からは撤退する

Status: Accepted

## Context

ADR 0020 の三層化（#775〜#778）が合流した時点で、HQ_ADMIN は `STAFF_MANAGE` の既定授与により店舗スタッフ管理面（第 2 層）へも降りられた。これは当初調査が定義した Owner 層（店長の任命・ロール定義・システム設定）の帰結ではなく、無店長空窗期の兜底として置いた局所の便法であり、その理由は店長設定（#778）の「新規作成して任命」が冷起動を解いた時点で消えていた。

管理境界の引き方には二つの学派がある。POS 学派（Square / Shopify / Toast）は Owner を超級利用者に置き、委譲は**加算のみ**で上からは引かない。企業 IAM 学派（Entra の User Administrator と Privileged Role Administrator、Okta の Help Desk Administrator と Group Administrator、職務分掌における「定義」と「授与」の分離）は**減算**で切り、上位者ほど日常操作から遠ざける。本裁定は後者を採る（裁定の全文は #762 の 2026-08-26 コメント）。

原則を字面のまま貫くと断裂する点が二つある。①「誰がどの店の店長か」は授与そのものであり、HQ が授与から完全に手を引くと店長を任命する者が居なくなる。②STAFF はロールを 1 つ以上持つ不変条件があり、アカウント作成は初期授与と不可分である。

## Decision

- **HQ 管理者の職責を四つの関心事のうち三つへ絞る**: A アカウント生命周期（停止・再開・パスワード再設定）／B ロール定義（`ROLE_MANAGE`）／C 統治層の授与（管理者の授権・店長の任命 — 任命は日常の職種管理でなく統治動作）。D 店舗スタッフの日常管理は `STORE_MANAGER` 専属となり、HQ は店舗の面から撤退する。
- **アカウント生命周期の受け皿として `STAFF_ACCOUNT_MANAGE`（Console.PLATFORM・既定 HQ_ADMIN）とアカウント管理面 `/platform/staff-accounts` を新設する。** 母集団は本人種別 STAFF の全アカウント（HQ 側・店舗側を問わない）。CAST / MEMBER は専用フローの領分で、id 直指しも 404 に倒す。
- **アカウント面は授与をしない — 構造的守衛。** 応答・要求の型にロール・店舗集合への書き込み口を持たせない。実行時の if でなく wire 契約で「アカウント面から授権は動かせない」を成立させる。
- **アカウント面に作成は無い。** 作成は初期授与と不可分のため、授与を伴う三つの面（管理者管理・店長設定・店舗スタッフ管理）に残す。
- **停止・再開はアカウント管理面へ一元化する。** 管理者管理 `PUT /platform/staff/{id}` の要求型から `enabled` を型ごと削除し、授与面はロール × 店舗集合だけを扱う。G4（自己停止の禁止）と G5（不減零）はアカウント面の停止経路にも課し、G5 の直列化は目録行ミューテックス → 利用者行の既存獲得順序を共有する。

### 保留線と既知の制限

- **授与権の `GRANT_MANAGE` への切り出しは保留する**（起票しない）。定義（面B）と授与（面C）は既に別 controller に分かれており、将来の切り出しは `@PreAuthorize` の字面とメニュー行の権限を替えるだけで足りる。
- 保留期間の既知の制限: 店舗側委譲権限を含む自作ロールは定義できるが、HQ 撤退後はそれを授与する面が無い（授与口は店舗スタッフ管理のみで、そこは委譲権限を含むロールを付与できない — ADR 0020 G1）。実需が出た時に `GRANT_MANAGE` の切り出しで解く。

## Consequences

- 撤退の実装順序は安全要件である。アカウント管理面（本 ADR の受け皿）が先に立たないうちに HQ の店舗面既定授与を撤回すると、店舗側ロールしか持たない退職者のアカウントを誰も停止できない真空の窓が開く。単店店長の解任の行き止まり（降格の不在）も、撤退が HQ の G3 免除を取り払う前に出口を用意しておく必要がある（票割りと辺は #762）。
- 撤退完了までの過渡期は、HQ_ADMIN が店舗スタッフ管理面と本アカウント管理面の両方から停止を行える。二重化は過渡期の既知状態であり、撤退（HQ の `STAFF_MANAGE`・`STORE_MENU_VIEW` 既定授与の取り下げ）が解消する。
- ADR 0020 Consequences 第 1 条（HQ の storeBridge 反転と店舗スタッフ管理の同画面兜底）は撤退の完了で差し替えとなる。HQ_ADMIN は跨店参照（`STORE_VIEW` / `ORDER_SET_MANAGE`）を保持する — 跨店の閲覧は平台運営の本職であり、細分が要る配備は自作ロールで組む。
- 停止はアカウント級操作としてロール構成に依らず全 STAFF に及ぶ一方、授与の変更は引き続き各授与面の守衛（G1〜G3・G5）の下にある。同一人物への操作でも、面によって通る経路と守衛が異なることは仕様である。
