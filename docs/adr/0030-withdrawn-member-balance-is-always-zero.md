# 退会済み会員の残高は常に零で、加算が生じた取引の中で再び消去する

Status: Accepted

## 決定時の背景

会員退会は未消費残の全量を WITHDRAWAL_CLEAR 仕訳で消去する。しかし退会後も、完了済み受注へのポイント巻き戻し（[ADR 0023](0023-point-rollback-is-an-explicit-operation-that-reverses-allocations.md)）は USE_CANCEL で利用分を元ロットへ戻すため、退会済み会員の残高が零から正へ動き得る。

候補は三つあった。退会済み会員の受注には巻き戻しを拒む（409）、戻った残高をそのまま残す、戻った残高を同じ取引で再び消去する。

## 決定

- 巻き戻しは会員の状態に依らず実行できる。店舗側の訂正が客の退会で不能になってはならず、台帳の USE_CANCEL / CANCEL の記帳も省かない。
- 巻き戻しの取引内で、会員が退会済みなら戻った未消費残を WITHDRAWAL_CLEAR 仕訳で再び消去する。理由は固定文言「退会済み会員のため消去」。
- 不変量は「退会済み会員の期限内残高は常に零」。退会時の消去と、加算を生む操作の内側での再消去の二か所で保証する。
- 退会済み会員への付与・来店特典・ランク更新の帰属物化は行わない。退会時に全 ACTIVE 関連を解除するので受注完了から会員へは到達しないが、物化処理側にも「退会済みなら飛ばす」守衛を置き、将来の別経路が残高を作らないようにする。

## 帰結

- 退会済み会員の台帳には USE_CANCEL と同額の WITHDRAWAL_CLEAR が対で並ぶ。残高が動かないのに仕訳が増えるのは意図した形で、明細の読み手には「退会済みのため消去」の理由で説明する。
- 台帳へ加算を生む操作を新設するときは、退会済み会員の分岐を必ず持つ。守衛は加算になりうる仕訳種別の枚挙テスト（ADR 0023 の二層目）に乗せる。
- 巻き戻しの請求側の相殺（POINT_REDEMPTION_OFFSET）は退会と無関係に働く。会員が受け取れないポイントの代わりに請求が戻るのではなく、台帳と請求はそれぞれの規則で独立に復元される。
