# 退会した利用者は電子メールと LINE ID を保持し、一意性は未退会の行だけに掛ける

Status: Accepted

## 決定時の背景

会員退会は終端状態だが、同じ電子メールで再び会員登録できなければならない。`t_users` の `email` と `line_user_id` は全行一意であり、退会した行がそのまま残ると再登録を塞ぐ。

候補は二つあった。退会時に識別子を空にして解放する（置換）か、利用者に退会日時を持たせて一意制約を未退会の行だけに掛ける（部分一意）か。

## 決定

- 利用者は `withdrawn_at` を持ち、`email` と `line_user_id` の一意索引は `WHERE withdrawn_at IS NULL` の部分一意索引に置き換える。退会した行は識別子を保持したまま残る。
- 電子メール・LINE ID で利用者を引く箇所（認証、登録時の重複確認、LINE 連携）はすべて未退会の行だけを対象にする。退会した行は認証の候補にならず、`User.stop()` による停止と `credentialVersion` の加算で旧トークンも即時に失効する。
- 再登録は新しい利用者と新しい会員を作る。旧会員との結び付けは行わず、会員ごと一回の特典は新会員で再び受益できる。これは受け入れる — 防ぐには電子メールで会員を跨いだ追跡が要り、識別子の保持と再登録の自由を両立させた意味が薄れる。

## 帰結

- 退会済み会員は会員コードだけでなく当時の電子メールでも照会できる。監査と問い合わせ対応の根拠が消えない。
- 識別子による検索は「未退会」条件を伴う。条件を落とすと同じ電子メールの利用者が複数ヒットし、`findByEmail` 系は非一意で壊れる。一意性を DB だけに任せていた前提は無くなる。
- 退会は利用者の停止（`enabled=false`）と別の状態である。停止は可逆で識別子を占有し続けるが、退会は不可逆で識別子を解放する。
