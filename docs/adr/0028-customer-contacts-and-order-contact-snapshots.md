# 顧客連絡先と受注の受付時の写しを分離する

Status: Accepted（受注の顧客選択・受付時の写し・複数連絡先・用途別連絡可否・今回だけの業務連絡許可・店舗内拒否判定・ゲスト同意取り込み・統合プレビュー拡張は実装済み）

連絡先の一致による顧客の選択は、連絡の手がかりに受注と会員の帰属判断を担わせる。複数の連絡先や一時的な連絡先を扱うため、顧客連絡先を顧客から独立した行として管理し、受注には任意の顧客参照と任意の受付時の連絡先の写しを持たせる。顧客連絡先の参照を受注に強制せず、台帳の変更を写しへ反映しない。

店舗の受注入力では、電話一致による顧客の自動選択・自動作成を行わず、人が既存顧客・新規顧客・顧客未設定を選ぶ。認証済み会員の申請による顧客整備は継続する。連絡先の入力は、会員本人であることや連絡の許可を証明しない。

顧客側の連絡可否とは別に、その申請・受注だけの業務連絡許可を根拠付きで持てる。連絡のためだけに顧客台帳への登録を要求せず、販促には流用しない。顧客選択の有無や申請の確認前後にかかわらず、送信・再送直前に同店の全未統合顧客の同種類・同値の有効な拒否を調べ、拒否があれば先に根拠付きの明示的な許可変更を要する。この照会は連絡制限であり、本人同定や顧客の自動関連には用いない。申請の原文と根拠は不変の証拠として保持する。

顧客統合では連絡先を ID と由来ごと全件付け替え、同値の行も自動で消さない。優先指定と顧客資料はプレビューで人が確定し、移動した対象と前後の資料を記録する。これは顧客フィールドの静黙な合併ではなく、独立した連絡先記録の付替えである。墓標・会員関連の衝突拒否・自動取消なし・ポイントと既存受注帰属への非波及は維持する。

同値の行を残す整理では、削除や値変更によって共同制約を緩めず、残存行に用途別の制約と由来を引き継ぐ。これは新たな同意ではなく既存制約の維持であり、操作と履歴を一体で確定する。全行削除後の新規登録は未確認から始め、削除済みの拒否は引き継がない。

連絡先・連絡可否の履歴を持つ顧客は物理削除せず、連絡先の全件削除後も履歴を保持する。汎用の顧客アーカイブ状態を増やす代わりに削除を明示的に拒否し、監査根拠を失わない。資料と優先指定を変更する統合プレビュー・実行には CUSTOMER_MANAGE と CUSTOMER_MERGE の両権限を要求し、統合だけの権限から資料編集へ越境させない。

本決定は ADR 0009 の電話による受注照合と未関連受注だけに写しを持たせる条項を置き換え、ADR 0010 の付替え対象と人による資料選択を拡張する。会員帰属の確定時点と台帳の責務は変更しない。詳細は [顧客台帳仕様](../specs/0385-customer-contacts.md) を参照する。

今回限りの許可の HTTP 契約と送信側の呼び出し条件は [0961](../specs/0961-order-business-contact-permission.md) を参照する。

ゲストの同意原文・取得時刻の保持と、権限付きの明示取り込みの HTTP 契約は [0962](../specs/0962-guest-contact-consent.md) を参照する。
