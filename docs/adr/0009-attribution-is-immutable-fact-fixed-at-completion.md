# 帰属は完了時に確定する受注単位の不変事実として記録する

Status: Accepted

## Context

会員の来店可視性を関連（Customer–Member Link）経由の動的な解決で読むと、三つの未決が絡み合う。
関連を解除した瞬間にその店舗の来店が会員の視界から消える（追記型で不変のポイント台帳と非対称になる）。
関連成立以前の受注 — 電話照合由来の台帳行には他人の来店が混ざり得る — がどこまで見えるかが定まらない。
解除後に同じ台帳行へ別の会員が紐づいた場合、解除前の来店が誰のものかが定まらない。

また、関連そのものにも「どういう根拠で結ばれたか」の記録が無かった。HL7 FHIR `Person.link.assurance`
は根拠の記録に公開仕様上の先例を与えるが、その語彙は抽象等級（level1〜4）である。

## Decision

- **帰属は受注単位の不変の事実として、生まれる瞬間を二つに限る**: 完了の瞬間（完了時の関連解決。
  根拠 COMPLETION）と、事後申領の瞬間（伝票トークンの所持証明。根拠 RECEIPT_TOKEN）。解決の結果は
  受注帰属記録として**その場で確定**（材料化）し、以後は関連の状態に影響されない。会員の**来店履歴は
  帰属記録だけ**から読み、関連の区間を読み直さない。申請の出所記録は来店ではなく**申請の追跡**
  （確定前・謝絶）として別の読み口で並置する — 謝絶された申請や無効化で取り戻された受注が
  「来店」に混ざることはない。
- **帰属記録は会員の削除後も残る**: 会員参照は関連と同じく欠落し得るものとし（削除で消さない）、
  紐づけ時点の会員コードのスナップショットを持って履歴の監査可能性を保つ — 関連の履歴行と同じ紀律。
- **解除は以後にだけ働く**: 関連の解除は未来の帰属を止める操作であり、確定済みの帰属記録・ポイント・
  仕訳明細の店舗表示には波及しない。関連成立以前の受注は帰属記録が無いので見えない — 救済は受注
  1 件ごとの事後申領のみ。同じ台帳行に後から別会員が紐づいても、各会員に見えるのは自分の帰属記録
  だけであり、争いは構造上生じない。
- **関連は成立根拠を具体的な機構名の事実として持つ**: MEMBER_CODE（会員コード提示）/ MEMBER_REQUEST
  （会員申請の確定時自動整備）/ MIGRATION（旧システム移行由来）。FHIR 式の抽象等級は採らない —
  「どの等級か」は判断だが「どの機構で成立したか」は事実であり、等級が要る日が来ても機構名からの
  写像で導出できる（逆は不可逆）。根拠は行ごとに不変で、挙動を分けない（MIGRATION も全機能）。
  より強い根拠での再成立は解除→新しい行で表す。将来の機構（SMS 検証由来の照合等）の値は実装が
  着地する時に加え、予約しない。
- **誤紐づけの訂正は二層とも理由付きの人手操作**: 関連側は解除＋正しい会員での再成立。帰属記録側は
  理由と実行者を記録する**無効化**（帰属記録の唯一の訂正操作）。無効化はポイント台帳へ自動波及しない —
  台帳側の訂正は手動調整で別段に行う（宛先と経路は ADR 0012）。訂正を機械の級聯にしないのは、誤りの上に誤りを重ねる危険が誤りを残す
  危険より大きく、また受注取消の収束（取消連動）と意味が異なるためである。**無効化された受注は会員へ帰属しない
  状態へ戻り、事後帰属の対象に復帰する** — 伝票トークンを再発行できる。再発行分の申領期限は**意図的な
  例外**として再発行時点から 90 日で数え直す（通常発行は完了から 90 日 — 誤帰属の期間が本人の申領窓を
  食い潰したまま原期限を残すと、訂正が形骸化するため）。正しい本人は所持証明の窄門を通って来店を
  取り戻せる。訂正のために帰属の成立経路を増やさない。
- **電話番号は店舗台帳内の検索の手がかりに留める**: 受注録入の照合キーとしては維持するが、複数一致時は
  自動照合を断念して顧客未設定で成立させる（無帰属受注は正規の状態）。一致行の中に会員関連付きの行が
  あり得る以上、機械が 1 行を選ぶことは誤帰属の入口になる。ただしこの場合も、録入された連絡先（氏名・
  電話番号）を静黙に失わせてはならない — 受注は顧客の連絡先を自身に持たないため、黙って顧客未設定で
  進めると入力が消える。店員の明示選択を求めるか受注側に写しを残すか、具体の形は実装で決める。

## Consequences

- 履歴の読み手は帰属記録を読むだけでよく、「その時点で誰が関連していたか」の再計算が要らない。
  時間境界の論点（解除後・成立以前・別会員の後付け）はすべて記録の有無に還元される。
- 店舗が代理入力した**未完了**の予約は会員から見えない（帰属記録は完了時にしか生まれない。本人申請の
  予約は申請の出所記録経由で見える）。必要になれば関連経由の表示用読み口を別途設ける — 本決定の
  骨格には触れない。
- 移行由来（MIGRATION）の関連も初日から全機能で働く。確度による差別待遇が要る日が来れば、機構名の
  根拠から導出して加えられる。
- 訂正は稀で、理由の残る人手操作に限られる。台帳・帰属記録・関連のどれも行を削除しない。
- 誤帰属の訂正は、誤って付与されたポイントが**既に費消されている**場合、手動調整だけでは完了しない
  ことがある（利用の引き当ては残高までしか行えず、部分消費を作らない）。引き切れない場合の扱い —
  再発行の保留・損失の受容など — は本 ADR では定めず、運用の実例に基づいて別途裁定する。
