# 受注の帰属は顧客経路に一本化し、会員可視性は受注単位の帰属記録で与える

Status: Accepted

## Context

受注が「人」に着地する経路は二つあり得る。店舗が起こす受注は顧客（店舗台帳行）に紐づき、会員本人が
ポータルから申請する受注は申請者（会員）を記録する。完了時のポイント記帳先を決める会員解決をどちらの
経路に置くか、そして何の連絡先も残さない客の受注をどう扱うかが未決だった。

医療分野の HL7 FHIR は同型の構図（組織横断の身元 Person と組織ごとの役割 Patient）に対し、業務行為は
必ず組織ごとのレコードへ着地させ、横断身元を業務リソースから参照させないという制約を置いている。

本システムの通底原則は「電話番号は手がかりであって証明ではない。候補探索は自動でよいが、帰属の成立には
本人証明＋明示の確認が要る」。

## Decision

- 完了時の会員解決（ポイント記帳先）は「顧客 → 有効な関連 → 会員」の**一本のみ**。申請者の記録は
  申請の出所であって帰属ではなく、記帳・集計・取消のいかなる判定にも使わない。
- その保障として、会員申請の受注は**確定時**に当店の台帳行と関連を自動整備する。ログイン態が本人証明、
  当該店舗への申請が明示の確認であり、上記原則の両要件をこの経路は構造的に満たす — 来店時の会員コード
  再提示は要求しない。台帳行は氏名＝会員の表示名・電話空で作成する。謝絶・取下げの申請は台帳に行を
  作らない（確定時のみ作成）。
- **会員の来店可視性は、確定済みの帰属と申請の追跡から与える**: 完了時の関連解決も事後帰属も、いずれも
  受注単位の帰属記録として読む（確定の時点と読み口は ADR 0009）。申請者の記録は申請の追跡（確定前・
  謝絶を含み、申請の取消操作権もここ）を担う。関連は帰属を**成立させる機構**であって履歴の読み口では
  ない — 下流の履歴・集計・取消は帰属記録とポイント台帳を消費する。これにより事後帰属（関連を作らない）
  の来店も可視であり、関連の解除が過去の可視性を書き換えることもない。
- 顧客にも会員にも紐づかない受注（無帰属受注）は**正規の状態**。売上には数え、ポイントは記帳せず、
  店舗のみが見る。店側が会員アカウントを代理生成することはない — 会員化は本人の登録操作のみ。
- 事後帰属は**受注単位のみ**。証明は完了時に未帰属受注へ発行するワンタイムの伝票トークン（QR）の所持
  とする。受注 ID は時刻順で列挙可能であり秘密ではないため、番号入力は所持の証明にならない。同じ理由が
  トークン自身にも要求として跳ね返る — **トークンは暗号学的に予測不能な十分なエントロピーの乱数で生成
  する**。推測・列挙できないことが、所持を証明と認める根拠そのものである。申領期限は完了から 90 日
  （予約の先読み上限 90 日と対称の固定値）。**遅延申領の付与額は完了時点の規則で確定する** — 発行時に
  付与すべき額を確定して持ち、申領時点のポイント設定には影響されない（同じ会計が申領の早い遅いで別の
  ポイントになることを許さない）。無効・期限切れ・使用済みは同形のエラーで返し、受注の存在を漏らさない。
  成立の効果はポイント記帳と来店履歴表示に閉じ、店舗台帳（顧客行・行級の関連）へは波及しない。
- 行級の関連の成立は、その台帳行の過去受注のポイントを**遡及記帳しない**。遡及は受注 1 件＝トークン
  1 枚の経路のみ — 行の過去には電話の誤致で他人の受注が混ざり得るためである。

## Consequences

- **完了時の会員解決**の読み手は顧客経路だけを知ればよい。完了時に申請者へ fallback する設計は
  採らなかった — 解決が二経路の和を永遠に抱え、台帳行の無い来店ポイント（店舗 CRM から見えない客）
  という状態を生むためである。**下流の履歴・集計・取消**は帰属記録とポイント台帳を消費し、顧客経路を
  読み直さない（Decision 参照）— 関連を作らない事後帰属の来店も、この読み口でだけ漏れなく見える。
- 会員申請の受注でポイントが漏れる余地は、確定を経ない完了が存在しない限り構造的に無い。店員の追加
  操作にも依存しない。
- 自動整備により同一人物の台帳行が店内に重複し得る（電話由来の既存行と申請由来の新行。申請は電話を
  運ばないため突合できない）。誤帰属よりも重複を選ぶ判断であり、行の統合は将来の別決定に委ねる。
- 伝票トークンを受け取り損ねた客の救済経路は v1 に存在しない。店員の人手による救済（審批）は実運用の
  実例が出てから設計する。
- 受注取消のポイント収束は元取引（受注）単位で行われるため、事後帰属で積まれた付与も特例なく射程に入る。
