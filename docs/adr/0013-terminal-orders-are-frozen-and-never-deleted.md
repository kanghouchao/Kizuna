# 終端状態の受注は汎用更新せず、単件削除しない

Status: Accepted

## 決定時の背景

汎用更新と単件削除で、完了後の内容や取消理由を無記録で失わせる経路があった。完了はポイント・帰属の成立を伴うため、通常編集を止め、理由付き専用操作と訂正記録を分ける必要があった（#380 / #684）。

## 決定

- 汎用更新は COMPLETED / CANCELLED を拒否する。理由は財務ロックの新設でなく、無記録の裏口を閉じること。状態判定は共通化し、status を通常更新の要求型に持たせない。
- 取消は CONFIRMED → CANCELLED の専用操作。理由・実行者・時刻を残し、二度目は拒否する。理由は自由記述であり、集計分類ではない。読み出し時の実行者 FK は SET NULL により欠落し得る。
- 受注を単件で削除する口は持たない。誤登録も取消として残す。店舗単位の削除と FK 連鎖は別の可否判断であり、本決定では廃止しない。
- 申請は [ADR 0017](0017-order-applications-are-a-separate-record-from-orders.md) の別記録で受け、すべての Order は CONFIRMED で作成する。申請の謝絶にも同 ADR の理由必須規則を適用する。
- 完了後の内容訂正は [ADR 0019](0019-completed-orders-are-corrected-through-a-permissioned-gate.md) の ORDER_CORRECT 専用経路で行う。完了状態を戻さず、POINT_REDEMPTION 以外の明細・実績時刻・コーススナップショットだけを直す。他の通常編集項目と CANCELLED は凍結する。
- ポイントは訂正へ自動連動しない。全体の打消しは [ADR 0023](0023-point-rollback-is-an-explicit-operation-that-reverses-allocations.md)、誤帰属は ADR 0012 として分け、帰属無効化を受注取消の代わりにしない。

## 帰結

取消率は誤登録を含む。分類が必要になっても、統計を整えるために記録を消さない。会員応答の項目は許可リストで、店舗内部の取消理由を含めない。

逐次の二度目取消は状態違反 400、並行して同じ CONFIRMED を読んだ取消は楽観ロックで敗者が 409 となり得る。初回の理由・実行者を保護し、敗者を黙って成功させない。

店舗削除の許否は StoreRegistryService と DB 外部キーが決める。受注単件の削除禁止を、親店舗の破棄可否と同一視しない。未稼働の baseline 編集・開発 DB 再作成は DB 規約に従い、古い取消行への架空の理由補完は行わない。
