# スタッフ管理は三層に分かれ、店長は店長を作れない

Status: Accepted

## Context

現行 `STAFF_MANAGE` は「スタッフアカウントの作成・付与・停止」と「ロール定義の管理」を単一権限で覆い、保持者は HQ管理者のみ — 店長が自店のスタッフを管理する経路が無い。かといって権限をそのまま店長へ配ると「店長は誰が管理するのか」という階層の問題に行き着く。業界の同種プラットフォーム（Square / Toast / Shopify POS / スマレジ）は三層構造（Owner 層／委譲されたスタッフ管理／防提権ガードレール）に収斂している（調査と裁定の全文は #762）。

構造制約が一つ設計を縛る: `consoleOf` は PLATFORM 権限を 1 つでも持つ利用者を平台コンソールへ着地させ、routeGuard も同判定に従う。店長へ PLATFORM 権限を渡すと登録動線ごと反転するため、店長へ委譲する権限は Console.STORE でなければならない。

## Decision

- **`STAFF_MANAGE` を二分する。** `ROLE_MANAGE`（Console.PLATFORM・既定 HQ_ADMIN）＝ロール定義の改廃＋ HQ 側授与（管理者の管理・店長の任命）。`STAFF_MANAGE`（Console.**STORE** へ移転・既定 HQ_ADMIN + STORE_MANAGER）＝店舗スタッフのアカウント作成・編集・停止＋店舗側ロールの付与。アカウント作成も店長へ下放する — 現場で採用したスタッフを登録できなければ委譲が半分で終わる。
- **防提権は Square 型＋ 2 拡張。** 委譲付与できるのは店舗側ロール（構成権限がすべて STORE / SHARED）のみで、対象の店舗集合 ⊆ 行使者の担当店舗集合（付与時検証・不遡及）。Toast 型（対象の全権限を行使者も保持）は採らない — ロールの定義権が Owner 層にある以上、店長が授けるのは HQ が束ねた権限包（職位）であって権限の発明ではない。拡張 1: **委譲権限そのものは再委譲できない** — `STAFF_MANAGE` を含むロールは（既定でそれを持つ STORE_MANAGER を含め）委譲付与の対象外。除外を役職名でなく権限構成で判定するのは、授権が権限由来である以上、STAFF_MANAGE を包んだ自作の店舗側ロールは役職名の除外を素通りするため。店長が店長（相当）を作れると任命が第 1 層専属でなくなり三層が二層に潰れる。拡張 2: **編集・停止というアカウント級操作も同じ境界で縛る** — 停止は事実上の解任であり、付与だけ縛っても提権面が残る。
- **Owner は「人」でなく守衛。** `is_owner` は導入せず、「有効な **ROLE_MANAGE 実効保持者**が 0 になる操作の拒否」で最後の管理者事故を防ぐ。判定は役職名（HQ_ADMIN）でなく実効権限 — 管理が ROLE_MANAGE を含む自作 HQ 側ロールへ移った配備でも正しく数える。検査と変更は**直列化を伴う** — 計数検査だけでは、最後の 2 人が同時に相互降級して双方の検査を通り 0 になれる。Owner のアカウント属性化（削除不能・明示譲渡）は SaaS 化（テナント開設）の領分。代価: 管理者同士は相互に停止・降級できる（最後の 1 人を除く）。
- **権限コードの再利用は未上線だから許される。** STAFF_MANAGE の Console を PLATFORM→STORE へ書き換える変更は、自定義ロールが実在しない前提でのみ安全（目録行は削除不能で、自定義ロールが FK で参照し得るため、上線後は既存保持者の挙動が静黙に変わる）。**上線後に同種の語義変更を行う場合は、新コードの鋳造と旧コードの明示退役が必須。**

## Consequences

- HQ_ADMIN が STORE 権限を持つため storeBridge が true へ反転し、HQ は店舗コンソール入口を得る。店舗スタッフ管理は HQ・店長が同一画面を使い、無店長空窗期の兜底も HQ の同画面行使で足りる。「HQ は storeBridge=false」を前提にした断言・記述は陳腐化する。
- ロール×店舗集合は外積のまま（#523）: 「A 店の店長・B 店の平スタッフ」は表現できず、任命は本人の担当店舗集合全体を店長化する。per-store ロールは実需が出た時の別票。
- **既定授与の追加は守衛と同票でなければならない。** STORE_MANAGER への STAFF_MANAGE 既定授与を、旧 /platform/staff の門替えと防提権守衛より先に入れると、店長が旧泛用 API で任意ロールを任意店舗集合へ付与できる無守衛窓が開く（実装順序は #762 の票割りが規定）。
- 同店で STAFF_MANAGE を実効保持する者同士（店長・委譲ロール保持者）は互いに見えるが編集・停止はできない（解任相当の操作を第 2 層へ漏らさない）。
- 店長の可授ロール一覧は店舗側 API が「付与できる集合」へ絞って返し、防提権述語（店舗側ロール・STAFF_MANAGE 含有の判定）はサーバ側単源に置く。
