# 緊急昇格は独立した実体と短命な昇格トークンで表し、時限のロール授与では表さない

Status: Accepted

## Context

[ADR 0021](0021-hq-admin-retreats-from-store-daily-operations.md) の撤退により、HQ の既定授与には店舗コンソール
資格になる権限が無く `storeBridge` は false である。店長が不在・失聯のとき、HQ が臨時に店舗台の書き操作を得る口は
無い。#382 要件 4 が挙げる緊急管理の最低条件は 6 項 — 個人アカウントでのログイン / 利用理由または申請番号の記録 /
権限の有効時間の限定 / 再認証または多要素認証 / 変更前後の値を含む操作履歴 / 緊急権限の利用通知。

器の候補は二つあった。**時限のロール授与**と、**独立した緊急昇格実体**である。前者は現行の認可モデルと噛み合わない:
権限は発行済みトークンの claim で判定され、授権変更は次回ログイン反映が既定方針である（ADR 0022）。授与しても
発動者が再ログインするまで効かず、時限で取り下げても既発行のトークンは効き続けるので、失効を別機構で作り直すことに
なる。加えて「ロール×店舗集合」という通常の授与語彙へ、期限付きで自動消滅する別種の行を混ぜる。

自己昇格の可否は単独運営の現実が決める — 承認者を置ける体制が無い。自己承認は Entra PIM / GCP PAM が一級の構成
として支持している（調査は #837）。裁定の全文は #834・#835 の各コメント。

## Decision

- **器は緊急昇格実体（`t_emergency_elevations`）+ 短命な昇格トークン。** 発動時に通常 claim へ昇格分を重ねた
  トークンを再発行する。時限のロール授与は採らない。
- **自己昇格は可、入口は新設権限 `EMERGENCY_ELEVATE`**（Console.PLATFORM・既定授与 HQ_ADMIN）。誰が昇格できるかは
  ロール定義（ADR 0021 面B）の既有語彙に残す。
- **一発動一店舗**。昇格 claim は指定した 1 店舗ぶんの Console.STORE 全権限（`storeBridge` 語義を含む）を有効化する。
  他店舗への同操作は集合作用域の検証が拒む。
- **再認証はパスワード再照合**（既存 `AuthenticationManager`）。要件は「再認証**または**多要素」なので MFA 基盤は
  新設しない。再照合はいかなる書き込みよりも先に行い、失敗した発動が記録を残さないことを巻き戻しでなく順序で保証する。
- **有効時間は一律 60 分・選択不可**。延長は再活性化で行う — 新しい再認証と新しい行になり、各回が痕を残す。
- **記録は追記型**: 一発動一行・削除なし・変更は状態遷移と撤回欄の記入のみ。字段は発動者・対象店舗・理由（必須・
  自由記述）・発動時刻・失効時刻・状態・撤回者・撤回時刻。**申請番号の専用欄は設けない** — 外部チケットシステムが
  現存せず要件は「理由または申請番号」なので、理由必須で充足する（番号があれば理由文中に記す）。汎用の「権限事件
  履歴」表は建てない（汎用監査は #395 の領分で、先行して小さく建てるのは同票の分散実装禁止に反する）。
- **トークンは単一の claim 組立点を通す。** 第二の組立経路を作らない — ADR 0022 が依拠する不変量である。トークンの
  失効期限は記録の失効時刻をそのまま渡す（両者で別々に 60 分を数えると、監査で復元した区間と実際に効いていた区間が
  食い違う）。
- **撤回は実体の終了標記 + 発動者の `credential_version` 増分**（ADR 0022 の再利用。並行の失効機構を新設しない）。
  撤回できるのは `EMERGENCY_ELEVATE` 保持者で、本人の早じまいを含む。自然失効はトークンの期限だけで完結し、清掃処理も
  昇格トークン専用の毎要求検査線も要らない。
- **昇格中の操作に elevation_id を配線しない。** 各域の敏感な書き込みは既に操作者と時刻を持つ（ADR 0019 の
  `corrected_by` / `corrected_at` + 前値快照、ADR 0023 の巻き戻しの実行者・理由）。「この発動で何をしたか」は
  操作者 × 有効時間帯で各域の記録から再構成する。トークンに載る `elevationId` claim は、#395 の汎用操作履歴が昇格を
  操作文脈として載せる時に連結が自然に得られるための錨に留める。

## Consequences

- **撤回は発動者を全端末からログアウトさせる。** 緊急権限の濫用場面で通常のセッションごと断つのは欠陥でなく仕様で、
  撤回者が発動者と別人でも同じである。
- **発動しても元のトークンは失効しない。** 昇格トークンと通常トークンは期限切れか撤回まで併存し、発動者は昇格を要さ
  ない操作を元のトークンで続けられる。
- **期限切れの昇格を撤回する口は無い**（撥ねる）。既に効力の無い昇格に版を進めても、発動者の通常セッションを巻き添えに
  するだけで昇格は 1 分も短くならない。
- **「昇格中に何をしたか」を一覧する読み口は #395 まで無い。** #382 要件 4 の残り 2 項（変更前後の値を含む操作履歴・
  利用通知）は #395 が記録形・通知形を定める。通知の載体が現存しない今、本効力内で通知基盤は新設しない。#382 の当該
  受け入れ基準は #395 の落地で全緑となる。
- **失効機構は増えない。** 昇格トークンも資格情報の版の相等比較に載るため、ADR 0022 の不変量（単一の発行点・
  fail-closed・時刻を解釈しない）はそのまま保たれる。
- `EMERGENCY_ELEVATE` の新設は既定授権の承認台帳とカウンタ守衛（`PermissionCodeTest` の 2 件・
  `DefaultGrantApprovalTests`・`PlatformStaffManagementIT` の目録件数）の更新を伴う。権限行の播種は enum 宣言から
  導出されるので移行スクリプトは要らない。
