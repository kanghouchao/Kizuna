# 明細の承諾は追加型の時点記録で、訂正は承諾を失効させない

Status: Accepted

## 決定時の背景

本人が日別の報酬明細を読む口はあるが、「読んだ上で認めた」という記録は無い。精算確認・財務ロック・支払証明は Kizuna が持たないと決めており（GLOSSARY「月次給与明細」の避ける表現）、この記録はそれらの代用になってはならない。一方で受注・実績・条件・ボーナスは完了後も訂正でき、当日の額は読むたびに現算される。認めた後に額が変わったとき、記録をどう扱うかが要点になる。

## 決定

- **承諾は追加型の時点記録。** 本人が承諾するたびに、本人 Cast・店舗・営業日と、その時点の三項（受注報酬・保証補差・ボーナス）の額と根拠（計入した受注と発生済み報酬、閉じた実績の合計時間と保証の判定、計入したボーナス）の写しを 1 行として追加する。行は書き換え・削除・撤回しない。当日実績の「行の存在が出勤確認」、受注帰属記録と発生済み固定報酬の「完了時点の事実は訂正に追随しない」と同じ族。
- **訂正は承諾を失効させない。** 「その時点に示された内容を本人が認めた」は訂正後も真である。表示状態は読むたびに導き、保存しない。判定はこの順で止まる — 承諾できる日でなければ「承諾不可」（内容が定まらない日に写しの照合をしない。過去の承諾があれば併せて示す）、行が無ければ「未承諾」、現在の内容と同じ写しを持つ行が一つでもあれば「承諾済み」、それ以外は「承諾後に変更あり」。承諾済みを任意の行で判定するのは — 最新の行だけを見ると、A → B → A と訂正が戻った日は A の行が既にあるため再承諾が行を増やせず、永久に変更ありに留まる。差分の表示には最新の行を使う。**内容の要約**は、額と根拠をすべて含む写しをサーバが正規化して作る識別子（ダイジェスト）で、額が同じでも根拠が違えば別の値になる。同内容の重複は（本人・店舗・営業日・内容の要約）の一意制約で構造的に防ぎ、鍵の衝突は既存行を返す。
- **承諾の意味は「示された内容を認める」。** 閲覧の事実ではなく、異議の放棄でもない。放棄まで読ませると労務上の署名の体裁を帯び、システムが生産してよいものではなくなる。
- **書けるのは本人だけ。** 店舗・管理者の代理承諾と、誰による取消も置かない。代理を許した瞬間にこの記録は店舗側の確認に変わり、置かないと決めた精算確認が裏口から戻る。店舗は報酬明細書の日別行で承諾状態を読むだけで、権限コードは増やさない（本人側の書きは本人種別、店舗側の読みは明細書の既存権限）。
- **承諾できる日は内容が定まった日だけ。** 営業日が終了し、保証の判定が計算待ち・未設定でなく、三項のいずれかが零でない日。未確定の日を承諾させると、issue が禁じる「未確認を確定合計に見せる」ことを本人の手で起こすことになる。
- **承諾は本人が見た内容に対して行う。** 本人側は明細書で受け取った内容の要約を期待値として送り、サーバが同じ読み取りスナップショット内で現算した要約と照合し、違えば 409 で差し戻す。保存も一意化も、サーバが現算した側の値で行う。完了が取得時の受注の版を名指すのと同じ形。

## 検討した選択肢

- 翻せる確認フラグ（訂正で未確認へ戻す）: 誰が戻すか・戻した後の再確認が何回目か・戻しの監査、という新しい状態機械を要する。写しを持たないので「何を認めたか」も残らない。不採用。
- 自然月単位の承諾: 月合計は計算待ち・未設定の日が一つでもあれば存在せず、日額保証は日ごとに計算して相殺しない。月は日の和でしかない。不採用。
- 店舗在籍（CastEnrollment）を鍵にする: 同店の退店・再入店で一日が二つの在籍に割れる。保証の計算は既に本人・店舗・営業日で歴史在籍を合併している。不採用。
- 本人による撤回行: 承諾が何も放棄しない以上、撤回に意味が無く、二種類目の行と「撤回後の再承諾」の定義だけが増える。不採用。
- 日別端点を三項へ拡張して日別画面から承諾する: 月の報酬明細書の日別行が既に三項を持つ。同じ計算をもう一つ端点に写すだけになる。不採用。

## 帰結

本決定の時点で実装は無い。承諾の表・本人側の端点・報酬明細書の日別行への承諾状態は、いずれも実装票 #1344 以後に存在する。以下はその実装が従う形。

- 報酬域で初めて本人・店舗・営業日の粒度で落盤する記録になる。remuneration モジュールが持ち、店舗作用域の列を持つ。
- 承諾行が業務正本で、同一取引で監査事件（金額のみ、根拠の写しは載せない）を追記する。本人自助の出勤希望提出・特殊サービス受諾と同じ扱い。
- PDF と日別・月別の受注報酬明細は変えない。承諾状態が載るのは本人側・店舗側の報酬明細書の日別行だけで、月の表示は承諾済みの日数を示すに留まり、「月の確定」は存在しない。
- 退店後も、その店舗に歴史在籍があれば過去日を承諾できる。本人の報酬明細の参照権と同じ条件。
- 日額保証を一度も設定していない店舗では、四時間以上の出勤がある日の保証の判定が未設定のままになり、その日は承諾できない。未設定と 0 円を区別する #387 の規則の帰結であり、保証を使わない店舗は 0 円を設定して初めてその日の承諾が開く。閉じた出勤が四時間未満で未終了の記録も無い日は、条件の有無によらず保証の対象外と判定されるので、受注報酬かボーナスがあれば承諾できる。
