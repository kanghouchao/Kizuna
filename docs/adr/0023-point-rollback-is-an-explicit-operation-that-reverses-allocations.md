# ポイントの巻き戻しは受注を宛先とする明示操作で、利用は引き当ての逆転で元のロットへ戻す

Status: Accepted

## Context

[ADR 0013](0013-terminal-orders-are-frozen-and-never-deleted.md) は受注取消を終端操作として定め、
[ADR 0019](0019-completed-orders-are-corrected-through-a-permissioned-gate.md) は完了後の内容訂正を
権限付きの門に閉じたうえで「ポイントへは零自動波及」を決めた。台帳の側には受注 1 件を根拠とする付与を
まとめて打ち消す `cancelForOrder` が実装だけ存在し、**どこからも呼ばれていなかった**。#381 要件 3
（受注を根拠とするすべての付与が追跡・取消できる）は、この呼び手の不在によって履行されないままだった。

呼び手の候補は二つある。受注取消（CONFIRMED → CANCELLED）への機構配線と、人が起こす明示操作である。

## Decision

- **受注取消へは配線しない。** 付与も利用も、完了と伝票トークンの事後申領という 2 つの契機でしか記帳
  されない。取消できるのは確定済みの受注だけなので、**取消の瞬間に打ち消す仕訳は構造上存在しない**。
  配線は恒に空振りするコードであり、「取消がポイントを戻す」という誤った期待だけを残す。
- **呼び手は明示操作「ポイント巻き戻し」**。受注 1 件を宛先に、理由必須で操作者が起こす。権限は
  `POINT_ADJUST` を再用する — 手動調整と同じ重さの台帳直接操作であり、新権限は線を増やすだけで
  守る対象が同じになる。
- **対象は完了した受注だけ**。確定済みの受注を許すと、記録だけが先に書かれたあとの完了が付与を積み、
  その付与を打ち消す手立てが残らない（二度目の巻き戻しは撥ねられる）。取消済みには打ち消す授受が無い。
- **完了後訂正の門とは機構を繋がない。** ADR 0019 は不変で、門は台帳を読みも書きもしない。訂正結果の
  画面がこの操作への導線を示すのは画面レベルに留める — 門が手当ての実行有無を知り得ないという ADR 0019
  の論証は、導線が増えても変わらない。誤完了の救済のポイント側は分工する: **全否定は巻き戻し、差額は
  手動調整、誤帰属は帰属訂正（ADR 0012）**。
- **誤帰属の清掃に巻き戻しを使ってはならない。** 巻き戻しは事後申領を恒久的に拒む。正主がその後
  正当に申領する経路まで塞がれる。
- **利用の打ち消しは引き当ての逆転**として表す。新しい仕訳種別 `USE_CANCEL` は元の利用を参照し、
  金額は正、引き当ては元の利用が引いたロットへ<b>同量を返す</b>鏡像として持つ。消費済み量の集計を
  符号付きにすることで、返した分がそのまま元のロットの残りへ戻る。
  - 再付与型（新規ロットを作る）は採らない。#807 以降、期限付きロットは特典と手動調整の産だけであり、
    再付与では期限付きのポイントが無期限のロットへ洗い替わる。期限は元のまま保つ。
  - `USE_CANCEL` は加算だが**新しいロットにはならない**。残高計算のロット述語は「加算」ではなく
    「加算かつ利用取消でない」であり、これを取り違えると返した分が二重に残高へ現れる。
  - 返った残量が既に期限切れなら翌日の失効批が拾う。期限を保つことの自然な帰結であり、意図した挙動。
  - 1 件の利用への逆転は高々 1 回。元の仕訳への参照の部分一意索引が守衛になる。
- **操作は受注キー控の記録として物化する**（`t_point_rollbacks`）。受注 1 件につき高々 1 行で、理由・
  実行者・時刻を持ち、二度目は 409 で撥ねる（初回の理由・実行者を静默 no-op で吞まない — ADR 0013 の紀律）。
  - **記録は台帳の仕訳がゼロでも書く。** 伝票トークンの付与予定額は完了時点で固定され、再発行でも
    計算し直されない。記録が無ければ、無帰属のまま清零訂正された受注でも 90 日窓内の申領が原額の付与を
    積み直せる。**事後申領の入口はこの記録で拒み、台帳の仕訳の有無では判じない。**
  - **クライアント冪等キーは要求しない。** 操作記録の一意性が収束を担う。ADR 0007 の射程は自然キーを
    持たない自由書き込み（手動調整）であり、受注を自然キーに持つこの操作は当たらない。
- **内部順序は利用の逆転 → 付与の取消**。本受注の利用が本受注の付与を消費していた場合、逆順だと付与の
  未消費分が小さいまま数えられ、取り戻せる量が減る。
- **取消の仕訳に理由を持たせる。** 巻き戻しが積む取消・利用取消はどちらも人手の操作の産物であり、
  理由が無いと残高が動いた説明が台帳の外にしか無くなる。
- **不変量は二層で保証する**（#381 要件 3）。行内で表せるもの — 付与・利用の受注 ID 非空、利用取消の
  元仕訳参照必須 — は DB CHECK。行内で表せないもの — **どの種別が加算になりうるか** — は生産側の強制と
  枚挙する守衛テストで押さえる。加算になりうる種別を足した者に、その種別が受注から辿れるかを判断させる。

## Consequences

- 取消済みの受注にポイントの手当てが要る事態は起こらない。起きているなら完了を経ているはずで、その受注は
  巻き戻しの対象になる。
- 巻き戻し済みの受注は事後申領を永久に拒む。正しい本人が後から申領する余地も同時に消えるため、**誤帰属の
  清掃には使えない**（上記）。この非可逆性は操作面に明示する。
- 消費し切った付与は取り戻せない。未消費残だけが取消の対象であり、費消済みの差額の手当ては手動調整の
  領分である（ADR 0012 の Consequences が残した未裁定と同じ地点に落ちる）。
- 残高計算のロット述語が「加算」から「加算かつ利用取消でない」へ変わった。加算になりうる種別を足すときは、
  それがロットになるかを別に決めること — 両者は同じ述語ではない。
- 台帳の明細に `USE_CANCEL` が並ぶ。会員向けの表示は持ち主から見た出来事の名で呼ぶ（「利用取消」）。
- 巻き戻しは受注行と伝票トークン行を押さえてから会員の加算ロットを押さえる（ADR 0016 の向き）。
  トークン行を押さえるのは事後申領と直列化するためで、押さえないと申領は操作記録を見ず、巻き戻しは
  申領の付与を見ないまま双方が成立し、打ち消せない付与が残る。
