# 媒体は店舗の媒体一覧の ID で参照し、改名で記録の帰属を動かさない

Status: Accepted

広告費・受注・応募者は、媒体を名前の文字列ではなく店舗ごとの媒体一覧（`t_media`）の ID で持つ。媒体別集計・受注あたり記録広告費・採用効果は媒体 ID で突き合わせ、表示名は現在の媒体名とする。参照は `(medium_id, store_id)` の複合外部キー（NO ACTION）で同じ店舗の媒体だけを許し、参照のある媒体は削除せず停止する。

これまで三者は互いに参照しない自由記述の文字列を持ち、集計は保存された名前の完全一致で突き合わせていた。名前の正規化や別名統合を避けたのは「名前が変わると過去の帰属が動く」ためだったが、その結果、表記揺れ（「シティヘブン」と「ヘブン」、全半角、空白）が別媒体や媒体未入力に落ち、費用と受注・入店が対応しなかった。安定した ID で参照すれば、改名は表示を変えるだけで帰属を動かさない。表記揺れは入力を一覧からの選択にすることで発生源を断つ。

## 検討した選択肢

- 名前の正規化・別名表: 揺れの規則を後追いし続け、規則の変更が過去の集計を書き換えるため不採用。
- 広告費の行を受注・応募者から参照する: 広告費は店舗×月の費用行で、同じ媒体でも月ごとに別行になる（前月コピーも新しい行を作る）ため、翌月には対応が切れる。不採用。
- 集団共通の媒体マスター: 広告費・受注・応募者はすべて店舗に帰属し、店舗を跨ぐ同一視の要件が無いため不採用。

## 帰結

- 過去時点の媒体名は復元しない。広告費の変更履歴だけは「誰が何を何に変えたか」の記録として、その時点の媒体名を写しで残す。
- 受注は知った経路（MEDIA / REPEAT / REFERRAL / OTHER）を持ち、媒体は MEDIA のときだけ持つ。媒体以外の経路と未入力を「媒体未入力」に混ぜない。
- 停止中の媒体は新しく選べないが、既に持つ記録はそのまま保てる（停止は新規選択の制御であって記録の訂正ではない）。
- 媒体は `advertising` ではなく独立した `medium` モジュールに置く。`advertising` は受注・採用の集計を読むため、そこに置くと受注・採用から参照したときに循環する。
