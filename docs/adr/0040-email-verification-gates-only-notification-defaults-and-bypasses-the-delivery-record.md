# メールアドレスの検証は通知の既定だけを左右し、検証メールは送信正本を通さない

Status: Accepted

## 決定時の背景

会員のメールアドレスはログイン ID を兼ねるが、メール・パスワード / LINE のどちらの登録経路も本人の入力をそのまま保存し、LINE もメールアドレスを渡さない。ADR 0039 はこれを理由に会員宛の通知の既定を業務・販促とも未確認とし、検証を導入した場合に業務の既定を許可へ改めるかは別の決定として残した。本決定がそれに当たる。

検証を導入すると、次の二つを決めなければならない。未検証の会員に何を許すか、そして検証メールをどの経路で送るか。通知の送信正本（NotificationDelivery）は業務を跨ぐ唯一の正本であり、「正本は一つ」の原則からは検証メールもそこに載せるのが自然に見える。

## 決定

- **検証が左右するのは会員の通知設定の業務の既定だけ。** 未検証の会員もログイン・会員コードの提示・ポイント・予約申請・伝票申領・退会・LINE 連携を制限無く使える。メールアドレスの役割はログイン ID と通知の宛先に限られ、店舗での本人性は会員コードが担うため、検証を機能の門にする理由が無い。ログインを塞ぐと LINE 登録の自動ログインと店頭での即時登録が壊れ、既存会員の一括未検証にも猶予が要る。
- **検証済みの宛先では業務の既定を許可にする。販促の既定は未確認のまま。** 会員の通知設定は本人の明示の選択だけを保持し、既定は解決のたびに検証状態から導く。明示の選択が常に優先し、本人は業務を拒否へ変えられる。
- **検証メールは送信正本を通さない。** 決め手は本文に秘密（トークン）が載ること — 正本は本文を不変に保存し、NOTIFICATION_VIEW の職員が読め、NOTIFICATION_SEND の職員が再送できる。加えて、正本は送信直前に用途別の連絡可否を解決するが、検証メールは同意より前に送る往復であり、定期処理の周期で届くものでもない。member モジュールが notification の `transport` をコミット後に直接呼び、失敗しても登録は成立する。検証メールは通知ではなく認証の往復で、会員の通知設定の対象外。
- **検証は宛先に束縛する。** トークンは発行時のメールアドレスに対して発行し、メールアドレスが変われば検証は無効になり、生きたトークンは失効する。変更口は別の決定だが、この不変量は変更口より先に固定する。
- **未検証の身分を自動で失効・退会させない。** 他人のアドレスを握った身分（本人の誤記を含む）は、本来の持ち主の登録を職員の代行退会まで塞ぐ。これを受け入れる — 自動退会は SMTP の不調時に有効な会員を一括で退会させる罠になる。
- **職員が手で検証済みにする口は置かない。** 検証済みは本人がそのアドレスを受け取れた事実であり、職員の目視では代替できない。

## 検討した選択肢

- 未検証ではログインを拒否する（一般的な形）: 登録直後の自動ログインが両経路で成立しなくなり、店頭で登録してすぐ会員コードを提示する流れが止まる。既存会員にも猶予期間が要る。不採用。
- 送信正本に用途 VERIFICATION を足して連絡可否の解決を免除する: DB の check は用途を列挙しないので追加は安い。しかしトークンが正本の本文に残り、職員の閲覧・再送の対象になる問題は用途を足しても消えない。不採用。
- 検証コード（本人がポータルに打ち込む数桁）: URL にトークンが出ないが、ログイン中の端末でしか完了できない。リンクはフラグメントで渡し画面が POST するので、GET で消費されず、別端末からも完了できる。招待の受諾と同じ形を採った。
- 未検証の身分を期限で自動退会させてアドレスを解放する: 上記の罠のため不採用。

## 帰結

- ポイント期限前案内は、検証済みで業務を拒否していない会員に届く。未検証の会員には本人が許可しない限り届かない（ADR 0039 のまま）。
- 未検証でもログインできるので、ログイン特典は未検証の会員にも付与される。ポイントは店舗で会員コードを提示して関連が成立しなければ使えず、検証の有無はこれを左右しない。
- 確認端点は匿名の POST であり、backend/AGENTS.md の匿名端点の四点を満たす。ログイン中のタブから開かれると陳腐な Bearer が付きうるので、Bearer の解決から除外する。
- `GET /me` に検証状態が加わる。権限と利用者種別は変わらないので資格情報の版は増やさない。画面は `GET /me` を layout の生存期間で保持するため、別タブで検証した直後のバナーは再読込まで残る。
- 検証メールは SMTP 未設定の環境では送れず、dev / e2e で検証を完了させる手段は実装 issue で決める。
