# 完了した受注は権限付きの門でだけ訂正し、採用条件の前値を保持する

Status: Accepted

## 背景と決定

終端凍結を維持しながら提供事実の記録を訂正するため、状態を戻す汎用更新と分離した、理由・権限・履歴付きの入口を使う（#380・#384・#931・#932）。

- 対象は COMPLETED のみ。CONFIRMED への回退、CANCELLED の訂正、予定・人数・担当・受付・備考・伝言の編集を許さない。誤取消は新しい受注で扱う（ADR 0013）。
- 訂正は `POST /store/orders/{id}/corrections`、成功は 201。ORDER_MANAGE と ORDER_CORRECT の両方、および非空白の理由を要する。ORDER_CORRECT は既定で店長へ付与し、設定の管理権限を追加要求しない。
- 変更できるのは実績時刻・コースの採用条件・編集可能明細。要求型に他の字段を持たせず、未知字段は 400 とする。
- コース・加算の選び直しは同店舗の歴史版本から名称・費用・分数・固定報酬を採る。削除済み設定も選択でき、現在価格へ置き換えない。加算の単価・報酬の直接入力を認めない。
- 延長は各回の正の整数分・零以上の費用・費用以下の固定報酬、割引は名称と正の整数円を要する。通常操作と同じ不変量を適用する（ADR 0018）。MANUAL_ADJUST は訂正でも直送でも拒否する。
- 既存明細は line_id の維持指定で採用条件を保持する。明細は編集可能行の全量を必須とし、空配列は除去。コース版本の省略は保持、実績時刻の省略は値なし。独立した延長分数の入力は持たず、延長行から導出する。

## 試算・競合・履歴

訂正前に試算し、請求・総時間・固定報酬と各明細の条件を確認する。保存では受注をロックして expected_version と confirmation_token を照合する。競合は 409、失敗した処理の履歴・費用・報酬だけが残る部分成功を許さない。

`t_order_corrections` は各訂正の前後快照・前後の受注版・原営業日・原完了日時を独立して保持する。操作者・訂正日時・理由・一意な訂正 ID とともに、本体更新と同じトランザクションで確定する。後値は flush 後の本体を再取得して写し、列の日時精度と明細 ID を確定する。後続の訂正や現在設定から過去の後値を復元しない。

店舗は ORDER_MANAGE、平台は ORDER_SET_MANAGE と授権店舗集合により履歴を照会できる。`after_version DESC, id DESC` の上限付き CursorPage を使い、カーソルを受注・作用域へ結び付ける。同時刻の訂正でも順序は受注版で確定する。履歴照会に訂正・設定変更権限は要求しない。

成功応答は訂正 ID、前後のコース・明細・請求・総時間・固定報酬・発生済み報酬、前後版、原営業日・原完了日時と訂正日時を返す。`order::result` の単件結果は最新訂正とその ID を含み、同境界のカーソル履歴から中間の変更記録も辿れる。受け手は訂正 ID で二重計上を除外できる。給与仕訳・実支払・イベント配信は含まない。HTTP 契約は [0935](../specs/0935-order-correction-history.md) を参照する。

## ポイントと救済の境界

POINT_REDEMPTION と POINT_REDEMPTION_OFFSET は訂正でも凍結し、追加・改変・除去を拒否する。利用ポイントを含む請求が負になる訂正は拒否する。割引後請求が固定報酬を下回ることは許し、割引で報酬を零にしない。

訂正サービスはポイント台帳へ依存せず、完了時の付与額・会員帰属を動かさない。付与は完了時点の事実であり、訂正で再計算しない。画面はこの事実と対象会員の台帳への入口を示し、付与差額を実行指示として提示しない。台帳の手動調整と受注訂正には二重実行を防ぐ関連がないためである。

未提供の誤完了を「任意調整で請求零」にする経路は持たない。固定報酬まで無効にする明示的な誤完了無効化とポイント抵销の接続は #384 の後続票で扱い、本票で実装済みとはしない。ポイント利用取消は ADR 0023 の専用機構を維持する。

特殊サービスも同店舗の歴史版本から採用する。現在の拒否・設定削除・改定は過去の提供事実の訂正を妨げず、未変更項目の採用根拠は保持する。訂正前の特殊サービス快照と訂正 ID を記録し、任意単価を入力しない。拒否・処置履歴は専用 CursorPage で閲覧でき、訂正履歴一般の照会とは区別する。

ポイント巻き戻しは元利用を残して同額の正の POINT_REDEMPTION_OFFSET を台帳返還と同一トランザクションで一度だけ生成する。通常編集・訂正では双方を保護し、請求のみを復元して固定報酬を変えない。詳細は [利用取消契約](../specs/0936-point-redemption-offset.md)。
