# 受注の請求・時間・固定報酬は採用明細から導出する

Status: Accepted

## 背景と決定

手入力の総額と内訳を別々に保存すると、何に対する請求・報酬かを説明できない。受注明細を正本とし、設定の変更を既存受注へ遡及させず、変更する項目だけを明示的に採用する（#380・#384・#931・#932）。

- 種別は BASE_COURSE / EXTENSION / SPECIAL_SERVICE / SURCHARGE / DISCOUNT / POINT_REDEMPTION / POINT_REDEMPTION_OFFSET / CREDIT_SURCHARGE。受注の MANUAL_ADJUST は通常操作・訂正・API・DB から撤去する。ポイント台帳の手動調整は別の専用機構として維持する。
- 基本コース料金は採用コースから一行だけ生成する。名称・価格・分数・固定報酬を直接入力しない。
- 延長は各回を独立した行として、名称・正の整数分・零以上の整数円・零以上かつ費用以下の固定報酬を保存する。無料延長は費用と報酬がともに零で、コースから比例計算しない。
- 加算は店舗設定から手動選択し、一受注に同一設定は一回まで。名称・費用・報酬と設定 ID・版本 ID・版本番号・採用根拠・採用日時を保持する。現在条件の直接上書きや数量入力を認めない。
- 固定割引は非空白の名称と正の整数円を持つ複数の行で表す。割引は請求だけを減らし、報酬を減らさない。割合割引・任意式は持たない。
- CREDIT_SURCHARGE は名称・金額入力を維持する。特殊サービスは受諾済みの条件を採用し、名称・金額を直接入力しない。決済固有加算の統合は未実装である。

## 導出と保護

保存金額は種別に応じた帯符号で、表示・要求では減項も正値とする。`total_fee` は全明細の和、`extension_minutes` は延長行の分数の和。総時間はコースと延長の和、固定報酬はコース・延長・加算の採用額の和である。

割引後・ポイント控除前の請求を付与基準とポイント利用上限に使う。割引・ポイント利用で固定報酬を減らさず、折引後の請求が報酬を下回ることは許す。請求の負数と整数上限超過は拒否する。項目除去・コース変更で割引が過大になっても、システムは割引を自動修正しない。

POINT_REDEMPTION は完了時に台帳と対で作るシステム専有行。通常入力・訂正では追加・削除・変更できない。利用取消は ADR 0023 の経路で扱う。ホテル代・交通費・釣銭・回収・返金・実支払・精算は本内訳の外である。

## 明細の維持と再確認

既存の編集可能行は `line_id` だけで維持を指定する。所有する受注を検証し、種別・名称・金額・分数・報酬・版本・採用日時を一切変えない。新規・選び直しだけを操作時点の設定で解決する。手入力行の変更は旧行を除いて新しい条件を送る。通常更新の明細省略は保持、空配列は編集可能行の除去を意味する。

コース変更でも他の明細を保持する。完了時は採用コースを変えず、完了後訂正の加算は歴史版本を選ぶ（ADR 0019）。設定の改定・論理削除は未変更の受注・訂正前快照へ回写しない。

作成・申請確定・編集・完了・訂正は試算と明示確認を要する。保存時に同じ入力を再解決し、操作者・店舗・対象・入力・計算結果を結ぶ confirmation_token を照合する。採用条件・会員資格・ポイント規則等の変化は 409 とし、前回と今回の内訳・版本・費用・報酬・時間を示して再確認させる。残高だけの変動で結果不変かつ利用可能なら保存できる。受注の取得時版本は expected_version で照合する。

## 永続化

pre-launch baseline を直接編集する。明細には store_id、duration_minutes、remuneration、service_id、revision_id、revision_number、adoption_basis、adopted_at を持つ。親受注と店舗の複合 FK、および設定版本・設定・店舗の複合 FK が店舗を跨ぐ採用を防ぐ。親受注の FK は CASCADE、設定版本は NO ACTION で暗黙削除しない。

加算の部分一意索引は同一受注・設定の重複を、CHECK は種別・符号・分数・報酬・設定参照の有無を守る。跨行の合計は集約で導出し、認証 HTTP と PostgreSQL の統合テストで保存・再照会・競合を検証する。互換層・増分移行は設けない。

## 特殊サービスの採用

特殊サービスの名称・価格・固定報酬は受諾済み設定版本から生成し、任意価格の入力経路を持たない。採用版本と受諾イベントを受注に保存し、設定の改定・削除で更新しない。本人拒否は未完了受注に未処理記録を作るが、金額・進行状態を変えない。修復時は除去・改選・担当変更の前後を同じトランザクションで記録する。店舗行を最初にロックし、設定・在籍・本人操作と保存・開始・完了を直列化する。


### 受注完了の固定報酬とポイント

受注の `completed_at` は受注自身の完了日時であり、会員帰属日時とは独立する。完了時に項目別固定報酬合計を `accrued_remuneration` に保持し、原 `business_date` へ帰属させる。未完了は予定報酬、取消は発生なし。割引・ポイント利用・回収・返金は報酬を減らさず、提供内容の訂正だけが発生済み額を更新する。支払済み額ではない。

通常割引後・ポイント控除前の金額を利用上限と通常付与基準に用いる。作成・申請確定・更新・完了の試算は会員帰属先・利用資格・今回の付与結果を照合する。現在残高は利用時に再検証するが、十分な残高だけの変化で再確認を要求しない。完了の料金・報酬・台帳・帰属は同一トランザクションで確定する。

公開境界 `order::result` は原営業日・完了日時・担当在籍・項目別快照・発生済み報酬・受注版を含む単件結果を返す。給与集計・実支払・訂正イベント配信は含まない。HTTP 契約は [0934](../specs/0934-order-completion-remuneration-points.md) を参照する。

ポイント巻き戻しは元利用を残して同額の正の POINT_REDEMPTION_OFFSET を台帳返還と同一トランザクションで一度だけ生成する。通常編集・訂正では双方を保護し、請求のみを復元して固定報酬を変えない。詳細は [利用取消契約](../specs/0936-point-redemption-offset.md)。
